## 目标与整体结构

目标是固定资源与工作量下，让既定 PSRL 策略训练 step 更早完成，初始化和清理也必须报告。单条命令更快、GPU 利用率更高、某个批次提前，只能用来解释这个目标，不能直接替代它。

[![模型请求、环境资源、同机卡池和训练反馈的当前结构](../experiments/env-current-layout.png)](../experiments/env-current-layout.svg)

同一 Agent 轨迹交替走两条路径：模型请求交给 SMG 网关，环境命令交给 EnvRouter。完整轨迹与评分先进入队列，满足题目组和策略版本条件后才成批训练，再同步权重给推理副本。EnvRouter 不替代模型路由或样本版本规则。

Native 与 Compose 两种容器提供者共用 GPU 作业提交、取消和归还协议。Command 只在两条命令之间选择同节点其他卡，容器、文件、CPU 和主存留在原处，不搬运行中的 CUDA 进程。显式共享先尝试独立环境卡，全部不满足才考虑已绑定推理卡余量，基础配置不会扫描任意训推卡。

## 已探索的方向与取舍

| 层次 | 当前有什么 | 下一步边界 |
|---|---|---|
| 资源与执行底座 | 显存预算结合实测准入，episode／command、同机池、定向清理及可选 MPS | 安全预算不是硬件隔离，各 benchmark 仍需分别接入 |
| 推理余量与整卡角色 | 常驻共享与整卡借出均有完整 PSRL 证据 | 整卡完整作业未提速，恢复未实机触发，训练卡借用未实现 |
| 自动持卡 | 根据可信执行能力和可选成本建议，在会话准入时选一次 | 没有通用理解任意命令，也未证明自动选择稳定超过手工配置 |
| 性能与容量 | 独立推理与环境画像、离线分区回放，多个静态并发实测 | 缺混合干扰画像和在线联合控制，整体训练预测仍明显低估 |
| 状态放置 | 亲和、等待／重建、版本身份和准备复用原型 | 先证明自然复用频率，简单亲和和常驻进程是必要对照 |
| 训练依赖调度 | 已发现未来批次适配挡住当前评分、长准备挡住同步 | 批次优先、阶段准入和提前准备仍待算法与真实对照 |
| 时间敏感评分 | 已有竞争导致选优错误及简单保护证据 | 由另一会话探索，本主线采用执行时间不进入奖励的任务 |

Env Service、整卡调整和同步重叠默认关闭，配置启用及实测收益是不同状态。详细条件以[架构能力表](../knowledge/01-架构与执行/01-Env架构_现状与完整执行流程.md#4-已实现与尚未完成的边界)为准。

## 最关键的实验证据

统一主基线是**同次冻结实现的 episode 静态环境池、满池排队**。历史多数静态对照实际是 command，因此共享数字只能算相对 command 的增量。最新1200秒窗口补测已完成两步851.44秒训练、1564.18秒完整作业，历史720秒失败记录不参与速度排名。跨次结果仍需注明超时与选卡差异。

本任务每个题目组采两条轨迹，每条有两条 GPU 命令和三次模型请求。四步实验每步六组，累计 `4×6×2＝48` 轨迹、96命令、144请求。两步则为24轨迹、48命令、72请求。累计数不代表同时并发，环境工具内部更新不等于策略训练 step。

| 对照与工作量 | 观察 | 可以说到哪里 |
|---|---|---|
| 3环境＋1推理，另固定2训练，四步 | Command 静态上限四1036.81秒，共享965.42秒，静态上限五898.98秒 | 共享比同上限训练少6.89%，但提高静态并发更快。共享完整作业仅少0.25% |
| 初始 2 环境＋2 推理，另固定 2 训练，两步 | Command 静态训练 569.87 秒，常驻共享 611.00 秒 | 该轮共享后的训练时间多 7.22% |
| Episode 主基线与重叠交接补跑，两步 | Episode 完整用时 1564.18 秒，重叠交接补跑 963.73 秒 | 完整作业用时相差 38.39%，包含跨次启动和运行配置差异 |
| 权重同步提前，四步 | 控制等待接近零，模型请求尾延迟下降，训练未见可归因收益 | 重叠仍是环境准备期，额外 GPU 进程占用限制因果解释 |
| 离线预测 | 解码配置留出平均误差2.20%，新配置完整训练时间低估约27%～29% | 可帮助筛选，不能将局部预测精度当作整体收益承诺 |

所有完整条件和日志入口由[九轮分区实验](../experiments/09-资源分区_静态卡池与推理余量共享.md#实验总览每一轮验证了什么)维护。六步和四步的早期正结果保留在[实验总览](../experiments/01-实验总览_调度收益与证据范围.md#当前训练实验有哪些结果)，不同工作量不作跨轮速度排名。两步三组策略梯度均为零，证明链路完成，不证明学习质量改善。

还有一些负结果影响选题：复杂联合放置未稳定超过简单亲和，PostTrain 热模型的后续评分更快但短批次总时间未胜常驻进程重载，自适应测量未胜固定保护两轮。这些边界提醒我们先比较简单而充分的方案。

## 当前研究问题与下一步

值得研究的具体问题是：**一条难以随时暂停的环境命令，既可能填满推理空档，也可能阻塞当前批次完成或权重发布，怎样选择时机才能让多步总时间更短？** 泛称动态分卡、性能建模、依赖优先已有先例，学术增量需要真实场景与强对照证明，尚未确定论文贡献。

先做[完整优先级表](05-调度研究_研究全景与证据详解.md#接下来可以做什么优先级与验收边界)中的 P0，基于已完成的episode补测，补齐同放置协议、同期限的配对归因。然后考虑两类简单策略：借卡观察期提前保留一个可撤销候选，避免刚决定借卡就被新长命令挡住；优先完成当前训练批次所缺的工作，同时检查是否拖慢下一批。

例如 A 是当前批次最后一条评分，B 是下一批次的新适配。先让 A 执行可能更早开训，但让 B 等也有代价。比较应覆盖多个连续 step，包含推理减速、准备、同步与清理，不能只报告 A 提前了多久。复杂预测放在简单策略之后，只有能改进实际决策才值得增加维护成本。

共享同步重叠、整卡恢复及训练卡借用分别有自己的正确性边界。前者已覆盖准备阶段，恢复缺完整训练实机证据，训练卡借用仍是提案。任务接入、状态复用和调度预测不要混在一个未经验证的“全自动系统”结论里。
