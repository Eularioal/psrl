# Env 实现、实测收益与后续规划（2026-10-28 阶段报告）

> 当前工程待办见 [工程审查与修复顺序](../knowledge/engineering-review.md#8-对照阶段路线图后的当前工作顺序)，2026-11-10 已局部对照源码复核。下文仍保留历史阶段边界。

> 后续 GPU 任务接入进展与研究方向见 [GPU 任务接入现状与规划（2026-11-10 更新）](science-gpu-bench-status-and-roadmap.md)。本文保留原阶段条件和结果。

> **历史阶段报告**：本文的“当前”和后续规划均限定到文内核对版本。现有架构请读[当前设计](../knowledge/current-design.md)。原生 GPU 接入和 MPS 同容器并发已在后续实现，本文保留原阶段实验和判断，不用它裁定这些功能现在是否存在。

> **核心结论，截至 2026-10-28**：Env 已具备 science / Harbor 路径的资源准入、跨任务 GPU 命令排队、统一作业执行和归属清理能力。在一次人工高显存压力的真实 PSRL science 三步训练对照中，OOM 尝试从 18 次降到 0 次，训练步骤累计耗时减少 **54.24%**，含初始化和清理的总时间减少 **27.59%**。收益来自减少失败重试，不是 CUDA 计算本身加速。
>
> 低压力下尚未证明稳定提速。可选 eBPF 进程归属后端已通过双 Docker 容器真实 CUDA 验证，新的故障恢复、逐卡预算和辅助容器限制已通过 CPU 回归，但尚未合并成一版完成原生 science GPU 任务的端到端验收。下一阶段优先完成这一闭环，再做通用接入、调度优化和自动策略选择。

本文是可单独转发的项目状态说明。背景、架构图、实验条件、结果数据和后续规划均直接写在本文中，不需要其他文件或图片。状态截止到 2026-10-28 本次汇总核验的范围，其他并行开发中的改动不自动纳入。性能数字来自明确版本的实验，不能当作全部新改动的性能结论。最新实现包含尚未提交的开发内容，**实现与验证完成不等于已经发布部署**。
