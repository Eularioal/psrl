# PSRL 环境 GPU 调度：命令级借还与推理卡弹性分配

技术报告 · 2026 年 11 月 26 日 · 结果核对截至 13:28（北京时间）

## 摘要

使用 GPU 工具的智能体强化学习任务在策略推理、环境计算和策略训练之间交替。静态分卡能隔离负载，但会话在等待下一次模型回复时仍持有环境卡预算，推理副本也可能在环境排队期间空闲。本文在 PSRL、SMG 网关和 vLLM 上实现三种逐层增加的调度能力：按环境命令归还 GPU 预算、在独立环境卡紧张时共享常驻推理卡的余量、在推理低负载持续时出借整张推理卡。整卡交接允许已运行的环境命令保留设备，模型休眠经显存核验后再扩大环境准入。

当前证据呈现两类负载。环境卡预约容量相对批次需求紧张时，释放命令间隙和借用推理余量有机会减少采样等待。八卡 AIME 十步中，完整方案相对 Episode 静态池与 Command 静态池的完整用时分别少 **27.47% 和 16.77%**，但请求 P95 升至 11.96 秒。环境池足够容纳批次时，可回收的排队较少。CIFAR-10＋COCO 单步先导中，完整方案未触发共享或借卡，相对 Command 静态完整用时多 **4.62%**。这一差值尚未拆成确定的控制开销与运行波动，不能视为轻负载开销上限。

单步 AIME 还显示，训练阶段的改善可能被初始化与清理抵消。本文统一并列三种策略、训练阶段与完整时间，保留单步先导、两步历史和十步结果各自的工作量。六卡历史实验进一步验证命令借还与重叠交接的机制，其中首次交接从 98.11 秒缩至 5.19 秒。所有结果均为单次顺序测量，部分基线为跨窗口补跑。正式两步短档三场景共9组已全部完成，物理清理通过。相对Command静态的完整用时，普通AIME少17.49%，高显存少10.00%，视觉多14.42%；视觉差值主要来自初始化。高显存与视觉的十步长档继续执行。

**关键词**　智能体强化学习 · GPU 调度 · 命令级借还 · 推理与环境共享 · PSRL

本文的**完整方案**统一指 **Command 粒度借还＋推理余量共享＋整卡借用（重叠交接）**，配置标识为 command_elastic。是否实际发生共享或借卡由运行负载决定。本文的新增单步结果为历史先导实验，正式短档要求两步，三场景两步三组现已齐备。

## 1 引言

当智能体调用 GPU 环境时，一条采样轨迹可能先让策略模型选择动作，再启动环境程序计算，然后把结果送回模型决定下一步。这与连续生成一段文本的强化学习负载不同。轨迹的模型请求、GPU 工具调用与容器准备交替出现，某阶段释放的计算能力未必能被其他阶段及时使用。

以两张环境卡和两张推理卡为例。环境队列里有六条评分命令，推理卡上此时只有一个副本有请求。这时有三个选择。第一，继续使用环境卡，在现有会话等待模型时归还它的 GPU 名额。第二，把部分命令放到仍常驻模型的推理卡，代价是两类程序争用计算和显存带宽。第三，暂停一张卡上的推理副本，后续请求由另一副本承接，将腾出的卡暂时交给环境。第三种选择还要付出休眠和恢复的成本，并可能在新一波推理到达时等待环境退出。

本文在同一 PSRL 训练链路上研究三个问题。命令级借还能否减少整个策略训练批次的等待？允许环境命令在交接期间保留 GPU 能缩短多少交接时间？共享和整卡借用在多强的静态配置下仍有增量？本文给出实际接入、计时口径和反例，并以静态环境池、Episode 持卡作为主基线。

## 2 负载与调度目标

训练进程持有待更新的策略模型。采样时，SMG（模型请求网关）选择 vLLM 推理副本，智能体拿到模型回复后调用环境。EnvRouter 在执行前检查会话和设备预算，环境 Worker 管理容器、执行命令并返回结果。训练器收齐一个批次所需的轨迹后执行一次策略更新。异步预取允许下一批提前采样，受策略版本差约束。对于当前批次来说，最后一条必需轨迹的完成时刻决定它何时能进入训练，即使未来批次已经积累了很多数据。

本文以固定总 GPU 数量、固定训练步数及预定轨迹数下的**完整作业时间**为主要指标，同时记录累计训练 step 时间、轨迹完成率、交接时间和模型请求尾延迟。训练 step 的时间包含等待采样、计算训练所需的概率与优势，以及更新策略的时间。优化目标是更早收齐并处理这些批次，同时维持模型版本、容器状态和显存预算的约束。把一条环境命令提前，不一定会让批次提前。若还有一条评分命令更晚结束，训练器仍需等它。

## 3 系统设计

### 3.1 会话常驻与命令级归还

环境会话保留容器、工作目录以及 CPU 和主存占用。Episode 模式在首次环境申请获准后一直保留 GPU 预算，直至轨迹终止且清理完成。Command 模式只在 GPU 命令准备、执行和返回阶段持有这份 GPU 预算，下一条命令再申请。调度器在确认 GPU 进程与显存已归还后才复用预算。若配置了同节点命令池，后续命令可选择同一宿主机的另一可用设备，容器文件和 CPU 主存仍在原节点，运行中的 CUDA 进程继续留在原卡。

[![固定环境卡、推理卡与训练卡，以及 Episode 和 Command 在同一轨迹间隙上的 GPU 预算对照](partition-episode-baseline.png)](partition-episode-baseline.svg)

**图 1　会话持续持卡和命令归还的对照（教学示例）。** 只剩一个可用环境名额。A 在第 20 秒结束第一条命令，等模型 30 秒后还要算 20 秒。B 在第 20 秒到达，需要计算 20 秒。忽略归还开销时，Episode 让 B 等到第 70 秒，最后第 90 秒结束。Command 让 B 在第 20～40 秒使用 A 归还的名额，A 第 50 秒回到 GPU，两条轨迹在第 70 秒前都完成。若 B 结束晚于第 50 秒，A 的第二条命令也会排队。实测短间隙的反例见第 5 节。

### 3.2 显存准入与常驻共享

调度器优先尝试独立环境卡，其次尝试已出借的卡，最后评估仍有模型常驻的推理卡。每张卡同时检查预约、当前物理用量和设备并发上限。预约记录某条命令获准后允许使用的显存，即使它还在导入依赖。物理用量来自设备遥测，能看到已经分配但未必能归属的显存。所有用量统一为同一单位后，在单卡层面进行以下计算。

> **准入用量** = 设备实测用量 + Σ max(0，已有预约 − 已确认属于该预约的实测量) + 模型余量 + 新预约。

设备实测用量已包含能核验归属的那部分，因此每项预约只追加尚未兑现的部分。归属缺失时该项扣减取零。以 90 GiB 预算为例，设备已用 50 GiB，其中 8 GiB 属于一项 16 GiB 的已有预约。再保留模型余量 16 GiB、追加新预约 16 GiB，账面用量为 50＋8＋16＋16＝90 GiB。若那 8 GiB 无法确认归属，账面变为 98 GiB，新命令等待。在两种情况下当前实测都是 50 GiB，区别是调度器能否证实其中一部分已经覆盖预约。全卡预约并发、主机预算及共享状态仍需分别通过校验。显存账本是准入约束，任务真实用量和速度还取决于运行时行为。

模型余量覆盖模型进程的动态占用，包括推理时的缓存和临时工作区。KV cache 保存已有 token 的注意力键值，活跃上下文的数量和长度影响其使用需求。实际分配策略取决于推理引擎和配置。显存空间充足时，环境命令仍会和推理共享计算单元、显存带宽以及主机到 GPU 的传输带宽。因此实验同时记录模型请求延迟和批次完成时间。[5]

### 3.3 推理卡借出、恢复与权重同步

实验控制器每隔约 2 秒主动向推理前端询问未完成请求数，并读取网关队列和环境卡压力。只有环境存在压力、网关暂无积压、移除一个副本后仍有足够请求容量，并且低负载连续约 30 秒时，才允许出借。在两副本实验中，配置的容量为每副本 16 个未完成请求，低负载系数为 0.65，所以借出前的门槛为 (2−1)×16×0.65＝10.4，即整数请求总量最多 10 个，并满足其余条件。这一容量来自实验配置。控制器以约 6 秒的高负载窗口识别恢复需求。若采样间隔超过三个周期或请求查询失败，重新累计窗口。

借卡时，网关停止向目标副本分发新请求，该副本完成已经接手的请求。等待式交接在模型退场前还要等待已有环境命令归还。重叠式交接允许已有环境命令继续运行，排空阶段的新环境命令仍受常驻模型余量和共享并发上限约束。暂停生成和休眠之前暂时关闭新的环境准入。完成休眠后，调度器以设备总用量减去**同次采样中已确认归属的环境用量**，检查非环境用量是否回到指定上限之下。通过后才将该卡标为已借出，扩大环境容量。

[![排空模型请求期间沿用常驻预算，休眠通过显存核验后才扩大环境容量](partition-overlap-proposal.png)](partition-overlap-proposal.svg)

**图 2　重叠交接中的两次准入边界（教学预算）。** 90 GiB 的卡上，若模型用 40 GiB、另留 16 GiB、命令 B 预约 16 GiB，排空前后最多还能接一条 16 GiB 的命令 C。模型退场并核验释放后，B 和 C 保留预约，D、E、F 才有机会进入。图给出可选实现的预算算例。真实训练观测到模型休眠时原命令仍运行，以及核验后的新增准入。

恢复路径先阻止新的环境准入，等待已有环境命令物理归还，再唤醒推理副本、拉取当前策略权重，发布新版本与网关路由。若角色转换失败，设备进入隔离状态以免两边继续使用。该原型的整卡转换针对单卡推理副本。训练 GPU 保持专用，现有推理实例也无需迁移到其他卡上。

常驻共享时，权重传输使用策略模型已有的分配，环境进程持有另一份模型。实现可以暂停 vLLM 读取和接收新请求，同时让已有环境租约继续，然后将新权重同步到推理进程的设备内存。这个优化与整卡休眠分开控制。四步实机对照中，最长模型控制等待从 32.01 秒降至约 18 微秒，实际的权重拉取主要落在环境准备阶段。该组训练 1014.76 秒，对照 969.96 秒，并存在额外 GPU 进程干扰。当前证据支持在有环境租约时提前同步，主要计算阶段的重叠与端到端收益仍待重复对照。

## 4 实验方法

**平台与任务。** 当前八卡主对照固定两张训练卡、三张推理卡和三张独立环境卡，策略模型为Qwen3-8B，环境任务覆盖AIME适配及评分、CIFAR-10分类与COCO图像描述。六卡历史对照在同类H20节点上运行真实PSRL采样、训练与版本通路，固定两张训练卡、初始两张推理卡和两张独立环境卡。策略模型为 Qwen2.5-3B-Instruct。受控 PostTrain 工具在容器内适配 Qwen3-4B-Base 的最终归一化参数，再用保留的 GSM8K 样本计算平均负对数似然。得分为其相反数的指数，执行时间与硬件速度不进入得分公式。策略生成可以改变学习率与回复长度，训练使用真实模型和环境命令。

**工作量。** 六卡历史主对照每组计划两个策略训练 step，每步消费六个题目组，每组两条轨迹，共 2×6×2＝24 条轨迹。一条轨迹依次执行策略请求、环境适配、策略请求、环境评分和策略收尾。因此每个完整作业累计执行 48 条 GPU 命令、72 次模型请求。所有完整组均执行 12,544 次环境模型内部参数更新。这些是适配工具的迭代，与两次 PSRL 策略训练属于不同层次。累计命令数量与同时准入数量也分别记录。

**基线与控制。** 主基线预先固定卡的角色。会话按固定卡序选择首张能满足资源需求的独立环境卡，全部不满足则排队，一旦准入持续预约至物理清理。Command 静态池保持专用环境卡，在命令间归还 GPU 预算。主要实验的独立卡预算为每卡 90 GiB、每条命令或 Episode 预约 16 GiB、每卡至多五个名额。共享组每张常驻卡至多两条环境命令，另给模型留 16 GiB 余量。历史 Command 静态组保留其当时的选卡规则。完整主基线补测与历史 Command 组的轨迹期限分别为 1200 和 720 秒，后续重叠补跑为 1200 秒。

**指标与计时。** 完整作业时间从各组执行入口计至进程、容器和设备物理清理完成，独立的依赖准备、源码冻结和容器 CUDA 预检在入口前。初始化计至首条轨迹开始，训练时间取该组全部 step 的累计，包含等数据。图中的其余时间包含计时边界之间的其他工作和清理。交接时间从控制器决定借出到该卡可按出借容量准入。训练完成、轨迹完成、命令返回、模型请求返回分别计数。失败组用完成量和超时证据评价。

## 5 实验结果

### 5.1 同一张图看收益与代价

本节以八卡三组实验为主对照。Episode 静态表示整轨迹持卡，Command 静态表示只归还命令间隙，完整方案再增加常驻推理余量共享与整卡借用。每个场景内部保持模型、数据和工作量一致，各场景之间的步数与任务量不同。

**表 1　四个场景分别检验什么。** 题目组产生两条轨迹，每条轨迹执行两条 GPU 命令、发起三次模型请求。这是本受控工作流的比例。

| 场景 | 每组工作量 | 初始环境池与任务需求 | 回答的问题 |
|---|---|---|---|
| 普通 AIME，单步先导 | 1步×10组×2＝20轨迹，40命令，60请求 | 三张环境卡，每卡最多五份预约，共15份 | 有排队时，短作业收益会否被启动成本抵消 |
| 普通 AIME，十步 | 200轨迹，400命令，600请求 | 同样15份预约，异步预取叠加批次需求 | 多批次下收益是否持续，推理延迟付出多少 |
| 高显存 AIME，单步先导 | 1步×6组×2＝12轨迹，24命令，36请求 | 每卡24 GiB预约、最多三份，共9份 | 模型与环境占用增加时，借卡还有多少增量 |
| 视觉混合，单步先导 | 1步×10组×2＝20轨迹，40命令，60请求 | 每卡上限16条，实际峰值16、4、0 | 原池充足时，完整方案是否引入额外时间 |

### 5.3 环境池充足时观察到了什么代价

视觉先导最初作为任务多样性对照加入，完成后的日志显示环境池容量充足，因而也提供了轻负载表现的证据。它使用MLGym的CIFAR-10分类与COCO图像描述组件，分别以准确率和BLEU-4评分。每组两类各10条轨迹，累计2560次工具内部更新。该实验检验受控工具工作流中的调度行为，完整benchmark排名与开放式Agent解题能力另需评测。

三张环境卡的命令并发峰值为16、4、0，40条命令全部在独立环境卡上执行，完整方案的共享与借卡均未触发。任务已经能进入原池，新增调度能力没有提供额外的排队削减。此时实验回答的是“在这种充足容量条件下，完整方案与Command静态的时间差有多大”。

## 6 讨论与局限

### 6.1 已验证的范围

**容量估计和批次时间。** Roofline 将给定算子的理想执行时间下界写成算术工作量除以峰值算力、访存量除以带宽，两者取较大值，因为计算与访存中更慢的一项限制理想吞吐。对 vLLM，合批复用权重读取，长上下文也会增加 KV 读取。已有单卡曲线用七种请求配置拟合解码时间，在另外六种配置上平均相对绝对误差为 2.20%，从短输入外推长输入时误差为 11.60%。预测整个 PSRL 轨迹批次时，简化模型仍低估实测约 27%～29%。差异来自预测对象的扩大，批次还要经历 CPU 与文件准备、命令竞争、后续评分、模型排队和权重同步。当前仅将模型用于筛选离线候选；请求门槛和命令上限仍是实测配置。[6]

**决定何时借与何时还。** 环境得到额外名额后，需要让当前训练批次中最晚完成的轨迹更早返回，收益才反馈到训练。代价包括推理副本减少后的排队、休眠和恢复、正在执行且不能立即释放的环境命令、共享引入的计算与带宽竞争。等待式与重叠式交接主要改变模型退场时是否等待旧环境命令，恢复时仍需等待归还。一种待验证的策略是按预计的批次完成时间选择动作，并约束模型请求尾延迟。它需要分别校准环境准备、计算和短期推理负载，并在混合负载和恢复场景下对比调优过的静态方案。

**有效性。** 六卡完整时间来自不同窗口的单次运行，源码快照、选卡规则、期限、初始化耗时和生成量有差异。八卡单步扩展已补测 Command 静态，其完整作业为 832.08 秒，低于动态的 875.27 秒，动态训练段则少 4.33%。普通AIME十步三组已齐备，其中Command静态为独立补跑；三个场景正式两步三组也已齐备，高显存和视觉十步仍在执行。各场景均为单次顺序比较。动态组合中的余量共享和整卡借用仍需单独消融。实机均在单节点测试，压力回升后的恢复、跨机环境迁移和训练 GPU 共享需要其他证据。核对的六卡两步、八卡单步、十步和新增两场景均记录零策略梯度，结论限于训练链路、版本通路与调度性能。

### 6.2 优先补充的实验

正式性能实验固定每种策略2步短档和10步长档，每档含Episode静态、Command静态、完整方案三组。三场景两步9组和普通AIME十步已完成，高显存十步Episode组已在私有节点初始化，之后继续其余两组及视觉十步三组。长短档冻结源码、模型、数据、每步工作量与单命令时限一致。当前不追加新benchmark矩阵；利用现有日志先分解启动与等待，下面其他新增实验仍为设计，启动前分别冻结预算与停止条件。

三次重复用于估计顺序运行的波动，尤其是高显存两步的10.00%收益和视觉两步的14.42%变慢；后者主要落在初始化。三组执行顺序可轮换，固定生成参数和任务种子，报告每次值及中位数、范围；样本量不足时不宣称统计显著。所有策略保留相同的预检、命令期限和失败判定，单列初始化、训练和清理。重复次数、最长运行预算与资源上限在启动前冻结。

强静态基线决定动态的研究价值。例如两训练卡固定时，动态从三环境卡借到第四张后变快，如果预先四环境、两推理已同样快，则主要收益来自选择了更适合这份稳定负载的分区。应在独立数据上校准静态配置，再让负载发生阶段变化，检查动态能否在两种需求之间持续选择更好的容量。这样才能判断在线调整是否具有额外价值。

恢复实验直接检验长命令的代价。假设借出卡上还有一条需运行 60 秒的命令，新一轮模型请求到达时无法马上取回这张卡，剩余副本承担请求并产生排队。实验应比较借卡阶段省下的环境等待与恢复阶段新增的模型等待，最终检查整批作业是否更早结束。这是教学场景，60 秒尚非本报告实测值。

当前零策略梯度任务能检验执行链、同步调用与调度时间。若论文进一步声称提升训练效率或维持学习质量，还需要允许策略动作影响奖励、产生组内奖励差异的任务，检查有效样本、非零更新、同步前后模型版本和同等质量下的时间。该目标应单独立项与设定预算。

## 7 相关工作

AReaL 通过异步 rollout 与训练提高利用率，并用策略版本差控制在途样本的陈旧程度。RollArt 将 agentic RL 各阶段分离，并在异构资源上组织环境执行与模型服务。DynaRL 将强化学习组件的放置和伸缩纳入动态调度。本文在异步采样的基础上，关注同一条轨迹反复离开、返回 GPU 工具所形成的细粒度空档，以及环境命令跨越推理副本角色转换时的资源所有权。[1–3]

Firepool 通过准备可恢复的容器和在空闲时回收显存，为 agentic/RL 负载提供共享的 GPU 容量。vLLM 的 PagedAttention 管理推理内部 KV 缓存，Roofline 提供算力和带宽约束下的性能上界。本文的调度判断使用环境命令边界、设备显存归属、网关流量及训练批次依赖。这些工作提供了状态管理、资源伸缩和性能建模的参照，研究贡献仍需在更广的同条件对照中验证。[4–6]

## 8 结论

当前实现支持逐命令归还、推理显存余量共享和整卡借用。重叠交接实测缩短了旧环境命令造成的等待。八卡十步中，动态组相对 Episode 静态池的完整用时少 27.47%，同时推理请求尾延迟上升；相对成功补跑的 Command 静态，完整用时少 16.77%，有跨运行窗口限制。高显存单步中观察到相对 Command 静态少 5.21%，视觉轻负载中则多 4.62%。这些结果说明收益与环境排队、可借容量和模型请求代价共同相关。正式两步三组现已齐备，高显存相对Command总时间少10.00%、视觉多14.42%，后者主要受初始化差异影响。下一步完成剩余长档，再做关键差异的轮换重复与调优静态对照，之后验证恢复阻塞和独立机制增量。
