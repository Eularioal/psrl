# Claude Code CLI 中手动运行终端命令的几种方式

整理日期：2026-09-14。

> **一句话结论**：在 Claude Code 交互式会话里，最快的方式是用 `!命令` 前缀直接执行并让输出自动进入对话上下文；也可以自己在终端跑完后把报错粘贴过来，或者直接口头让 Claude 调用 Bash 工具去跑。

## 三种方式对比

| 方式 | 操作 | 输出是否自动进入上下文 | 适用场景 |
|---|---|---|---|
| `!` 前缀 | 在输入框打 `!命令`（如 `!npm test`） | ✅ 自动进入，无需手动复制 | 想让 Claude 立即看到某条命令的执行结果/报错 |
| 只输入 `!` | 进入"bash 模式"，之后输入的内容都当作 shell 命令连续执行；按退格清空输入退出该模式 | ✅ 每条都自动进入 | 需要连续执行多条命令 |
| 手动粘贴 | 自己在终端（或其他会话）跑完命令，把报错文本复制粘贴到对话框 | 需手动操作 | 报错已经发生，命令耗时/有副作用不想重新跑 |
| 让 Claude 用 Bash 工具跑 | 直接用自然语言描述需求，例如"帮我跑一下这个脚本看看报错" | ✅ Claude 主动执行并读取 | 需要多轮调试、反复尝试定位问题 |

## 细节说明

- **`!` 前缀**：命令在当前会话的工作目录下实际执行，执行者是用户自己（不经过 Claude 的工具调用/权限确认流程），但产生的 stdout/stderr 会作为上下文的一部分展示给 Claude，Claude 可以直接读取并分析。适合类似 `gcloud auth login` 这种需要用户交互输入、Claude 不方便代跑的命令。
- **让 Claude 直接跑**：根据当前权限模式（见 [claude-code-permission-modes.md](claude-code-permission-modes.md)），可能会先弹出授权确认弹窗。优点是 Claude 可以自主反复调整命令、多轮排查，不需要用户来回复制粘贴。
