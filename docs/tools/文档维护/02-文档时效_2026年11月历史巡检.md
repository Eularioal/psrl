同一套调度代码可能通过 CPU 回归，但容器 CUDA、真实评分和训练仍各有条件。 验证是结论与证据的对应关系，不是每次必须爬完的一整套阶梯。 证据类别示意，不把进程存活、历史成功或测试替身写成本次完整训练。 [查看矢量图](../../_static/img/document-figures/evidence-levels.svg)。

各轮都在已有未提交修改上工作。表中的提交是核对基准，篇数是当时维护目录的数量。被忽略目录中的源码快照、日志与实验产物单独作为证据读取。

**静态检查**是读文档、检查链接和对照源码，适合发现失效路径、旧接口及相互矛盾的描述。**现场验证**则需要实际运行对应环境。三轮巡检没有新增 GPU 或训练任务。

判定过时要看用途：固定版本实验可以继续保存；声称“当前尚未实现”的正文，应随实现更新。例如旧报告测到整段任务占卡，现有实现已经支持逐命令借还，应更新今天的使用说明，同时保存旧实验的日期和配置。

## 6. 2026-11-05 再审计与清理

这一轮解决了四个容易影响理解的关系：

- **worker 与任务**：一次调用接收一条轨迹，一个 worker 可以跟踪多个异步任务；并发还受派发和准入限制。
- **模型命令与执行工具**：普通终端命令走 Harbor；受管 GPU 命令由 Science 工具分发，提交、等待和取消结果进入下一轮观察。
- **准入与后端**：关闭 Env Service 时走进程内计数，启用后走 Router；direct 和 MPS 的作业预算、并发方式分别说明。
- **配置转发与完整部署**：LMCache remote 的配置转发已有代码；完整远程部署仍需自己的验证。

同时删除已经实现的心跳、Harbor 准入、公共执行接入等旧待办，并将修复前故障留在历史材料。详细机制见[Agent Loop](../../psrl/01-PSRL原理_AgentLoop与工具调用.md)、[统一执行层](../../env-worker-deep-dive/knowledge/01-架构与执行/02-统一执行_EnvRouter与容器及预算策略.md)与[缓存配置](../../design/kv_cache.md)。
