## 怎样开始阅读

[从一道题理解 PSRL](../overview/reading-guide.md)串联样本存储、异步训练和参数分发，提供全局图与源码阅读顺序。[系统与实验术语速查](../overview/glossary.md)供按需查询进程、并发、显存、容器、租约和实验口径。

讲解深度按领域选择：报告直接使用 agent、训练、奖励、token 等常用概念，项目特有用法单独交代。容器与宿主的关系、磁盘文件与内存状态、并发执行和资源回收等系统机制，解释到足以理解当前结论；底层实现继续链接到专题。已有基础知识教程保留其原本的教学内容，读报告时无需先通读它们。

对外介绍 Science GPU 工作时，三篇材料各有用途：

| 文档 | 主线 |
|---|---|
| [简版介绍](../env-worker-deep-dive/milestones/science-gpu-bench-brief.md) | 解决什么问题 → 数字分类题的完整过程 → 任务类型与成果 → 研究价值 |
| [现状与路线图](../env-worker-deep-dive/milestones/science-gpu-bench-status-and-roadmap.md) | 验收层次 → 各题库覆盖 → 具体缺口 → 后续研究与对照 |

三篇正文解释必要的系统术语与项目约定。路线图中的环境长教程集中到接入详情，用 PostTrain、SWE 和 MLGym 三个真实例子说明，因此读覆盖状态时无需先读完容器与 Python 环境机制。

## 已经纠正的主要旧说法

| 主题 | 维护后的解释 |
|---|---|
| 陈旧度 | 训练使用由较旧参数生成的样本，版本差方向为训练版本减生成版本；版本界限与训练质量分别评估 |
| 参数同步 | `nixl_cpu` 经 CPU 驻留 PS Worker 搬运参数，控制与数据分开；推拉仍受锁和带宽约束 |
| 资源弹性与 TMS | 区分常规异步生成池、训练/验证共卡切换和可选的内存管理范围 |
| MPS | 按硬件代际说明客户端地址空间及提交机制，并区分项目已有的环境专用 MPS 与其他共享路径 |
| 同机独立 GPU | 设备身份已知时按实际设备集合判断；映射缺失时采用更保守的节点保护 |
| 训练与奖励 | 区分组内更新信号、优化器执行和模型能力提升；可验证奖励仍取决于检查器覆盖与隔离 |
| 运行配方 | 修正 SWE toy 数据与现行环境契约不匹配、ReTool 负分上限、Hydra 覆盖语法和部分过于绝对的指标判断 |
| 工具说明 | Codex、Claude Code 的操作说明按已核对资料更新，历史故障继续标明原版本 |

这些是本次有明确源码或资料依据的修正，不等于对所有外部依赖版本和全部性能结论重新认证。

## 历史实验与缺失证据怎样处理

历史材料按价值处理：重复的现状讲解合并到现状入口；独有的失败、修复前后对照、原配置与测量保留在历史文件或原始 JSON。过时的能力判断不再作为日常入口的结论。

日期早本身不足以判定实验应删除。例如修复前的 OOM 和记账失败，可以解释某个检查为什么必要。归档中会说明当时版本，当前能力则链接到现状页；不再让读者读到后面才发现前面描述已经失效。

固定提交的源码行号若已漂移，提供对应版本和 `git show` 恢复方式，不把旧行号跳转到现行文件中的无关代码。缺失原始图表或日志的历史报告会说明具体缺口，不再写成当前仓库可复算的结果。

关键实现变化回读相应源码，任务数字核对已有清单和 JSON，部分外部机制与工具行为查阅官方资料。读者定位的复核采用全目录定向检索与重点页面审阅，精简通用 ML 概念铺垫，保留解释系统行为所需的机制。历史 GPU 测量、训练效果、远端依赖环境及部署状态没有重新实测。
