## `/goal`：让当前会话持续推进一个目标

核对日期：2026-10-13。以下命令依据 OpenAI 官方文档；当前会话能力依据实际提供的目标管理工具；示例为教学假设，未运行项目测试，也未创建目标。

一句话结论：`/goal` 为当前会话设置一个持续目标，让 Codex 反复执行、验证和调整，直到达到完成条件或遇到停止条件，减少用户反复发送“继续”的需要。

### 它和普通请求的区别

普通请求同样可以包含读代码、修改、测试等多个步骤。`/goal` 增加的是显式的目标状态和跨轮次续跑机制：一轮工作结束后，只要目标尚未达成、仍处于活动状态且未触及限制，Codex 就可以从已有结果继续推进。它适合下一步依赖前一步发现的任务，例如复杂故障排查、迁移和反复实验。[官方 Goals 指南](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex)

这里的“轮次”指一次助手处理过程；一次处理过程内部可以调用很多次工具。“持续目标”指目标附着在当前对话上，不能据此假定它自动适用于所有新会话。

### 具体例子：修复一组测试

假设某项目共有 100 个测试，初始 12 个失败。可以在 Codex 对话输入框中提交下面这条示例指令：

```text
/goal 修复当前项目的测试失败，使约定测试集的 100 个测试全部通过。
不得删除或跳过测试，不改变现有公开接口。
先复现失败，再按根因修复；最后运行完整的约定测试集验证。
如果因缺少凭据或外部服务无法验证，说明阻塞点及所需条件。
```

示例中的数字是教学假设，不是本工作区实测结果。多行文字共同组成目标描述。

1. 先运行测试，确认 12 个失败及错误日志，建立初始状态。
2. 假设发现一个共同的配置问题，修复后剩余 3 个失败。此时已有进展，但没有达到 100 个全部通过，目标仍未完成。
3. 根据剩余错误进一步检查代码，修复后运行约定的完整测试集。
4. 只有 100 个测试全部通过，同时没有违反“不得跳过测试、不得改变公开接口”等约束，才能把目标标记为完成。
5. 如果最后 3 个测试依赖不可用的外部服务，应报告已经验证的部分和阻塞条件，不能把“无法运行”当作“通过”。

在这个例子中，“全部通过”是结果，“测试输出”是证据，“不跳过测试”是约束；失败日志决定下一步调查方向。这些内容让持续推进有明确的结束依据。

### 常用命令

以下命令输入在支持 Goals 的 Codex 对话框中，不是 Bash 命令。

| 命令 | 用途 |
|---|---|
| `/goal <目标描述>` | 设置持续推进的目标 |
| `/goal` | 查看当前目标 |
| `/goal pause` | 暂停目标 |
| `/goal resume` | 恢复已暂停的目标 |
| `/goal clear` | 清除当前目标 |

这些命令由[官方使用说明](https://learn.chatgpt.com/use-cases/follow-goals)列出。清除目标不应理解成撤销已经落盘的代码修改；目标管理和文件版本管理是不同操作。

### 当前会话能确认的机制

当前会话提供了 `create_goal`、`get_goal`、`update_goal` 工具，分别用于创建目标、读取目标状态与用量、更新完成/暂停/阻塞状态。它们是助手使用的工具名称，用户通常直接使用 `/goal` 即可。

工具支持显式指定 token 预算。Token 是模型处理文本时使用的计量单位，不等于汉字数，也不是运行秒数。预算用来限制消耗，不是“花到这个数量必然完成”的保证；本次没有核实界面的预算参数语法，因此不提供猜测性的 `/goal` 参数写法。

当前工具一次只能维护一个未完成目标。预算停止和使用量限制由用户或系统控制，助手不能自行解除。询问 `/goal` 的含义不会构成创建目标的请求，本次只做说明和文档留档。

### 怎样写得有效，以及什么时候使用

目标描述应交代：要得到什么结果、怎样验证、哪些约束必须保持、可操作范围，以及遇到什么情况需要报告阻塞。例如“让项目更好”缺乏可检查的终点，而上面的测试目标有明确的验收标准。官方建议将目标限定为一项可持续推进且可验证的工作，避免放入互不相关的任务清单。[官方使用说明](https://learn.chatgpt.com/use-cases/follow-goals)

对于“解释一个概念”“改一个变量名”等边界清楚的小任务，普通请求已经足够。对于需要反复观察结果再决定下一步的工作，持续目标更有用。

`/goal` 不保证任务一定成功，也不会改变当前工具权限；仍可能因用户暂停、预算、执行中断或确实无法推进的阻塞而停止。目标保留也不等于本地进程关闭后仍有机器替它执行，不应将其当成自动提供离线算力的功能。
